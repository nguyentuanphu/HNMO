## Gaps found on 2026-11-19

The owner's complaint: "the admin panel should host both S6.3 and S9 and manage the common
functions; players select S6.3 or S9 on the web; it doesn't do that".

1. **Worlds have no season.** `WorldDefinition` (#50, `/worlds`) has no game version field,
   the `/worlds` page can't make a Season 9 world, and the web game doesn't switch assets by world.
2. **The Season 9 data overlay is global.** Wave 4A's overlay (`client/web/bridge/GameFiles.cs`,
   `Data_S9` / `HNMO:S9DataPath`) makes Season 9 files win for every player when present,
   Season 6 worlds included. It must be per world: separate data roots (for example
   `/data/s6/...` and `/data/s9/...`), the web client using the root of the world the player picked.
3. **The server has no Season 9 game data.** `server/src/Persistence/Initialization` has only
   `Version075`, `Version095d`, `Version097d` and `VersionSeasonSix`. A Season 9 world needs its
   own initialization, written in HNMO's own code: maps 82-102 per the asset spec; items,
   monsters, skills, quests; plus Waves 4B-4D (elemental / pentagram / errtel, muun pets, master
   tree 330+, stat specialization, and the Season 9 maps and events).
4. **Players choose the season.** They pick S6.3 or S9 on the website and in the web game's
   server list (grouped by world, with a season badge). One admin panel manages both: shared
   functions for all worlds, season-only pages only for that season's worlds. S6.3 stays the
   default and must keep working exactly as now.
